
# Backend build plan (no auth, fal.ai video generation)

Goal: stateless-friendly pipeline that turns an uploaded property photo + an influencer reference photo into a real influencer-style video via **fal.ai (Veed)**. No login. Persist generations so your parents can see history and re-watch past videos.

---

## API provider — quick recommendation

You mentioned fal.ai's Veed model already works great, and asked about alternatives for cost.

**My recommendation: stick with fal.ai / Veed for now.**
- It already produces the output you want (influencer + property photo → talking-head reel). Switching providers means re-validating quality, which kills momentum.
- fal.ai bills per-second of GPU; Veed avatar runs are typically ~$0.10–0.40 per 10s clip — already cheap.
- fal.ai supports webhooks, so we don't need to poll.

**Alternatives worth knowing (not recommending now):**
- **HeyGen API** — purpose-built for avatar videos, very polished, but pricier (~$0.30–1.00/video) and stricter on avatar likeness rights.
- **Replicate (various avatar models)** — usually cheaper per-second than fal but quality varies model-to-model; you'd need to re-test.
- **Sieve / Sync.so (lipsync only)** — cheaper if you separate "generate narration audio" + "lipsync to influencer photo" yourself, but it's 2-3 API calls instead of one. Only worth it at scale.

**Suggested rule:** ship on fal.ai now. Only revisit if monthly bill > ~$50. I'll structure the code so the video provider is a single swappable module.

## What we'll build

### 1. Storage
Public bucket **`property-images`** for the property photo, and **`influencer-images`** for the influencer reference photo. Front-end uploads directly, gets back public URLs to pass into fal.ai.

### 2. Database
Single table **`generations`** (no `user_id`, no auth):
- `id`, `property_data` (jsonb), `property_image_url`, `influencer_image_url`
- `script` (text — narration generated by Lovable AI)
- `video_url` (text, nullable)
- `status` — `pending` | `processing` | `ready` | `failed`
- `fal_request_id`, `error`, `created_at`

RLS: open `select` and `insert` for anon (since no auth). `update` blocked from client — only the edge functions (service role) can update.

### 3. Edge functions

- **`generate-property-ad`** (existing, refactored) — Zod validates inputs, calls Lovable AI for the Indonesian narration script, inserts a `generations` row with status `pending` and the script, returns the row id + script.
- **`render-property-video`** (new) — takes `{ generationId }`, reads the row, calls **fal.ai Veed** with the influencer photo + property photo + script (or generated TTS audio), passes a webhook URL, sets status `processing`, stores `fal_request_id`.
- **`fal-webhook`** (new, public, `verify_jwt = false`) — receives fal.ai's completion callback, downloads the finished video, uploads to a `videos` bucket (so the URL is permanent), updates the row to `status = 'ready'` with the `video_url`. On failure, sets `status = 'failed'` + error.

### 4. Front-end wiring (`src/pages/Index.tsx`)
- Add a second upload slot for the influencer reference photo.
- On submit: upload both images → call `generate-property-ad` (script appears immediately) → call `render-property-video` (video card shows spinner) → subscribe to the row via Supabase Realtime → swap in the real video when `status='ready'`.
- Replace the hardcoded sample video with the real one.
- Add a small "Recent generations" list at the bottom (last 10 rows from `generations`).
